Direction A — one list, platform as a column. Every host lives in a single sortable/filterable list (the live app's .hrow grid, extended by one Hyper-V / Proxmox badge column). Differences are surfaced, not hidden:
• Platform accent tokens proposed: --hv azure, --pve Proxmox-orange. Badges, filter chips, and the migration source/target accents reuse them.
• Capability-aware columns. Proxmox exposes live CPU util; Hyper-V doesn't. The Capacity cell renders whatever the provider advertises — pve-node-02 shows a live CPU row, HV hosts show RAM+Disk allocation only. Same widget, capability-driven content.
• Capability-gated verbs. The "Migrate →" action is enabled on Hyper-V rows (we support HV→PVE) and disabled (greyed, with reason tooltip) on Proxmox rows. No verb a provider can't honour is ever live.
• Cluster awareness. PVE nodes carry a cluster tag; the header surfaces the cluster as a grouped unit while nodes stay individually addressable.
